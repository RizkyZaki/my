## 🤔 Apa Itu REST API?

REST (Representational State Transfer) adalah arsitektur API yang udah jadi standar industri sejak tahun 2000-an. REST menggunakan HTTP methods dan endpoints untuk akses data.

### Karakteristik REST:

```
GET    /api/users          → Ambil semua users
GET    /api/users/123      → Ambil user dengan ID 123
POST   /api/users          → Buat user baru
PUT    /api/users/123      → Update user
DELETE /api/users/123      → Hapus user
```

**Prinsip REST:**
- 📍 **Resource-based**: Setiap resource punya URL unik
- 🔄 **Stateless**: Setiap request berdiri sendiri
- 📦 **Standard methods**: GET, POST, PUT, DELETE, PATCH
- 📝 **JSON/XML**: Format data yang umum

## ⚡ Apa Itu GraphQL?

GraphQL adalah query language untuk API yang dikembangkan Facebook (Meta) tahun 2015. Berbeda dari REST, GraphQL cuma punya satu endpoint dan client bisa request data sesuai kebutuhan.

### Karakteristik GraphQL:

```graphql
# Single endpoint: /graphql

# Query - Ambil data
query {
  user(id: "123") {
    name
    email
    posts {
      title
      content
    }
  }
}

# Mutation - Ubah data
mutation {
  createUser(name: "John", email: "john@mail.com") {
    id
    name
  }
}
```

**Kelebihan GraphQL:**
- 🎯 **Client-driven**: Client tentukan data yang dibutuhkan
- 🔗 **Single endpoint**: Semua query ke satu URL
- 📊 **Strong typing**: Schema yang jelas dan type-safe
- 🚀 **No over-fetching**: Ambil data seperlunya aja

## 🔄 Perbedaan Fundamental

### 1. **Data Fetching**

**REST API:**
```javascript
// Butuh 3 request terpisah
const user = await fetch('/api/users/123')
const posts = await fetch('/api/users/123/posts')
const comments = await fetch('/api/posts/456/comments')
```

**GraphQL:**
```javascript
// Cukup 1 request!
const data = await graphqlClient.query(`
  query {
    user(id: "123") {
      name
      email
      posts {
        id
        title
        comments {
          text
          author
        }
      }
    }
  }
`)
```

### 2. **Over-fetching vs Under-fetching**

**REST - Over-fetching:**
```json
// GET /api/users/123
// Kita cuma butuh name, tapi dapet semua
{
  "id": 123,
  "name": "John Doe",
  "email": "john@mail.com",
  "phone": "+1234567890",
  "address": { ... },
  "preferences": { ... },
  "lastLogin": "2026-01-24"
}
```

**GraphQL - Exact data:**
```graphql
query {
  user(id: "123") {
    name  # Cuma ambil yang dibutuhin
  }
}
```

### 3. **Versioning**

**REST:**
```
/api/v1/users
/api/v2/users  # Perlu bikin version baru
```

**GraphQL:**
```graphql
# Cukup deprecate field, tanpa versioning
type User {
  name: String!
  email: String!
  phone: String @deprecated(reason: "Use phoneNumber instead")
  phoneNumber: String
}
```

## ⚖️ Perbandingan Performa

### REST API Performance

**Kelebihan:**
- ✅ **Caching mudah**: HTTP caching (GET requests)
- ✅ **CDN friendly**: Static resources bisa di-cache
- ✅ **Lightweight**: Request/response lebih simple

**Kekurangan:**
- ❌ **Multiple requests**: N+1 problem
- ❌ **Over-fetching**: Transfer data berlebihan
- ❌ **Under-fetching**: Perlu request tambahan

**Contoh N+1 Problem di REST:**
```javascript
// 1 request untuk users
const users = await fetch('/api/users')

// N requests untuk posts tiap user (100 users = 100 requests!)
for (const user of users) {
  const posts = await fetch(`/api/users/${user.id}/posts`)
}
```

### GraphQL Performance

**Kelebihan:**
- ✅ **Single request**: Ambil relational data sekaligus
- ✅ **No over-fetching**: Hemat bandwidth
- ✅ **Batching**: Query multiple resources sekali jalan

**Kekurangan:**
- ❌ **Caching kompleks**: Nggak bisa pakai HTTP cache standard
- ❌ **Query complexity**: Bisa bikin server overload
- ❌ **Overhead**: Parsing query tambahan

**Contoh Query Optimization:**
```graphql
# DataLoader pattern - solve N+1
query {
  users {
    name
    posts {      # Efficient batching
      title
    }
  }
}
```

### Benchmark Sederhana:

**📊 REST API:**
- Request count: 5-10 requests
- Data size: 100% (over-fetch)
- Cache strategy: Easy (HTTP)
- Complexity: Low

**⚡ GraphQL:**
- Request count: 1 request
- Data size: 40-60% (exact)
- Cache strategy: Complex (Apollo)
- Complexity: Medium-High

## 🎯 Fleksibilitas dan Developer Experience

### REST API DX

**Pros:**
```javascript
// Simple dan straightforward
const express = require('express')
const app = express()

app.get('/api/users', async (req, res) => {
  const users = await db.users.findAll()
  res.json(users)
})

app.get('/api/users/:id', async (req, res) => {
  const user = await db.users.findById(req.params.id)
  res.json(user)
})
```

**Cons:**
- Perlu maintain banyak endpoints
- Documentation manual (Swagger/OpenAPI)
- Frontend perlu adapt tiap ada perubahan

### GraphQL DX

**Pros:**
```javascript
// Self-documenting dengan schema
const typeDefs = `
  type User {
    id: ID!
    name: String!
    email: String!
    posts: [Post!]!
  }

  type Post {
    id: ID!
    title: String!
    content: String!
    author: User!
  }

  type Query {
    user(id: ID!): User
    users: [User!]!
  }
`

const resolvers = {
  Query: {
    user: (_, { id }) => db.users.findById(id),
    users: () => db.users.findAll()
  },
  User: {
    posts: (user) => db.posts.findByUserId(user.id)
  }
}
```

**Cons:**
- Learning curve lebih steep
- Setup awal lebih kompleks
- Perlu tools tambahan (Apollo, Relay)

### Developer Tools

**REST:**
- Postman
- Insomnia
- curl
- Swagger UI

**GraphQL:**
- GraphQL Playground
- Apollo Studio
- GraphiQL
- Insomnia (support GraphQL)

## 💡 Use Case Nyata

### Kapan REST API Lebih Cocok? ✅

#### 1. **Simple CRUD Applications**
```javascript
// Blog sederhana dengan struktur fix
GET    /api/posts
POST   /api/posts
GET    /api/posts/123
PUT    /api/posts/123
DELETE /api/posts/123
```

#### 2. **File Upload/Download**
```javascript
// REST lebih natural untuk file operations
POST /api/upload          // Multipart form-data
GET  /api/files/image.jpg // Direct file download
```

#### 3. **Public APIs**
```javascript
// Easy to consume, familiar untuk semua developer
GET https://api.github.com/users/username
GET https://api.twitter.com/tweets/123
```

#### 4. **Microservices Internal**
```javascript
// Service-to-service communication
GET http://user-service/users/123
GET http://order-service/orders/456
```

### Kapan GraphQL Lebih Cocok? ✅

#### 1. **Complex Data Relationships**
```graphql
# E-commerce dengan nested data
query {
  product(id: "123") {
    name
    price
    category {
      name
      parent {
        name
      }
    }
    reviews {
      rating
      comment
      user {
        name
        avatar
      }
    }
    relatedProducts {
      name
      price
    }
  }
}
```

#### 2. **Mobile Apps (Limited Bandwidth)**
```graphql
# Hemat data untuk mobile
query {
  user {
    name
    avatar(size: SMALL)  # Hanya ambil yang perlu
  }
}
```

#### 3. **Rapidly Changing Requirements**
```graphql
# Frontend bisa adjust query tanpa backend changes
query {
  posts {
    title
    # Besok butuh author? Tinggal tambah:
    # author { name }
  }
}
```

#### 4. **Aggregation dari Multiple Sources**
```graphql
# GraphQL sebagai API Gateway
query {
  user {
    name              # From User Service
    orders {          # From Order Service
      total
      products {      # From Product Service
        name
      }
    }
  }
}
```

## 📊 Kapan Pakai REST, Kapan Pakai GraphQL

### Decision Matrix

**🎯 Team Expertise:**
- REST: Beginner-friendly
- GraphQL: Need learning

**📊 Data Complexity:**
- REST: Simple/flat
- GraphQL: Complex/nested

**📱 Client Variety:**
- REST: Few clients
- GraphQL: Multiple (web, mobile, IoT)

**🌐 Bandwidth Concern:**
- REST: Not critical
- GraphQL: Critical

**💾 Caching Need:**
- REST: High
- GraphQL: Low-Medium

**🔓 Public API:**
- REST: ✅ Better
- GraphQL: Possible

**⚡ Real-time:**
- REST: WebSockets
- GraphQL: Subscriptions ✅

**🚀 Development Speed:**
- REST: Fast start
- GraphQL: Slower start, faster iteration

### Real World Examples

**Companies Using REST:**
- 🐦 Twitter API
- 🎵 Spotify API
- 💳 Stripe API
- 🗺️ Google Maps API

**Companies Using GraphQL:**
- 📘 Facebook
- 🎨 GitHub API v4
- 🛒 Shopify
- 📺 Netflix (internal)

### Hybrid Approach? 🤔

Bisa kok pakai keduanya!

```javascript
// REST untuk simple operations
GET  /api/health
POST /api/auth/login

// GraphQL untuk complex data fetching
POST /graphql
```

## 🙌 Penutup

Nggak ada yang "lebih baik" secara absolut antara REST dan GraphQL. Semuanya tergantung kebutuhan project kalian!

### Quick Decision Guide:

**Pilih REST jika:**
- ✅ Team masih belajar
- ✅ Project simple dengan CRUD biasa
- ✅ Butuh caching maksimal
- ✅ Public API untuk third-party

**Pilih GraphQL jika:**
- ✅ Data relationship kompleks
- ✅ Multiple client types (web, mobile, dll)
- ✅ Rapid feature development
- ✅ Bandwidth efficiency penting

### Tips Implementation:

1. **Mulai dari REST** kalau baru belajar backend
2. **Migrate ke GraphQL** kalau udah nemu pain points:
   - Too many endpoints
   - Over-fetching issues
   - Mobile performance problems
3. **Mix both** kalau ada use case yang berbeda

Yang penting, pahami trade-offs masing-masing dan pilih yang sesuai dengan context project kalian! 💪
